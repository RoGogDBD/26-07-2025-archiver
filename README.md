# <p align="center">Проект: Архиватор удалённых файлов по ссылкам</p>


## <span style="color: orange;"><p align="center">ОПИСАНИЕ</p></spawn>

Данный проект реализует HTTP-сервер, который позволяет создавать задачи на скачивание файлов из интернета (только `.pdf` и `.jpeg`), упаковывать их в ZIP-архив и отдавать пользователю. 

Пользователь:

- Создаёт задачу через API.
- Добавляет ссылки на файлы в задачу (максимум 3).
- Получает статус задачи и, когда архив готов, ссылку на него.

Сервер одновременно обрабатывает не более 3 задач. При превышении лимита возвращается ошибка.

Флаг -a задаёт адрес и порт сервера в формате host:port.
Если порт не указан, используется 8080 по умолчанию.

Пример запуска с флагом:
  ./bin/app -a=example.com:9000

Пример запуска без флага (используется localhost:8080):
  ./bin/app

## <span style="color: orange;"><p align="center">API</p></span>

### 1. Создание задачи

**Метод:** `POST`
**Путь:** `/task`

**Тело запроса:**

```json
{
  "name": "имя задачи (строка, не пустая, максимум 100 символов)"
}
```

**Описание:** Создаёт новую задачу на сборку архива.
Максимум 3 активные задачи одновременно. Если лимит достигнут — сервер вернёт ошибку.

**Ответ:**

```json
{
  "id": "uuid задачи"
}
```

**Коды ответа:**

* `201 Created` — задача создана
* `400 Bad Request` — неверное тело запроса (например, пустое имя)
* `503 Service Unavailable` — сервер занят, превышен лимит активных задач (3)

---

### 2. Добавление URL файла в задачу

**Метод:** `POST`
**Путь:** `/task/{id}/add`

**Тело запроса:**

```json
{
  "url": "ссылка на файл"
}
```

**Описание:** Добавляет URL файла в задачу.
Максимум 3 URL на одну задачу.

**Валидация:**

* URL не должен быть пустым
* Проверяется доступность файла по URL
* Поддерживаются только файлы с MIME типом `application/pdf` и `image/jpeg`
* Максимум 3 URL на задачу

**Ответ:**

```json
{
  "message": "URL added successfully"
}
```

**Коды ответа:**

* `200 OK` — URL успешно добавлен
* `400 Bad Request` — ошибка в теле запроса, URL пустой, превышен лимит URL в задаче, неподдерживаемый тип файла или ошибка доступа к файлу
* `404 Not Found` — задача с указанным id не найдена

---

### 3. Получение статуса задачи

**Метод:** `GET`
**Путь:** `/task/{id}/status`

**Описание:** Возвращает статус задачи. Если добавлено 3 URL, архив автоматически создаётся и доступен для скачивания.

**Ответ:**

* Если архив ещё не готов:

```json
{
  "status": "in_progress",
  "url_count": 2,
  "errors": []  // список URL, которые не удалось скачать (если есть)
}
```

* Если архив готов:

```json
{
  "status": "completed",
  "url_count": 3,
  "archive_url": "http://host:port/task/{id}/download",
  "errors": ["https://example.com/broken.pdf"]
}
```

**Коды ответа:**

* `200 OK` — статус возвращён
* `404 Not Found` — задача не найдена

---

### 4. Скачивание архива

**Метод:** `GET`
**Путь:** `/archives/{id}`

**Описание:** Загружает zip-архив с файлами задачи.
После успешной загрузки архив удаляется с сервера, а задача удаляется из хранилища.

**Коды ответа:**

* `200 OK` — архив передан
* `400 Bad Request` — архив ещё не готов
* `404 Not Found` — задача не найдена
